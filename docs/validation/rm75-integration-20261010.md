## 一、实际客户模型的碰撞表示

在用户已有整机模型开发包上执行 `scripts/prepare_rm75_collision.py`。三种 RM75 变体 b / 6fb / 6f 均得到相同结构：每种原 357 项碰撞几何转换成 64 个保守包围盒（底盘 24、躯干 24、机械臂 16），没有提高现有规划器的 256 项上限。

每个原碰撞几何的包围盒八个角点，都在其所属刚体坐标下逐项检查被新包围盒覆盖；不跨运动关节合并、不通过删除实体绕过检查。序列化后最大角点外溢量为 `-9.99999999945489e-07 m`，即仍有约 1 微米包容余量。详细分组、源实体编号和网格摘要在交付模型的 `collision-coverage.json`。

外观网格、关节原点/轴线/限位及惯量声明未改变；14 个去重后的实际外观 STL 共 68,804,176 字节。完整模型包经过再次独立转换，输出逐字节相同；所有配置与网格摘要均复核通过。模型 manifest SHA256：`f05793876e9333f77273cc99fcecf437e88e779db63baa30cfccaebbcddd35d4`。

保守包围盒可能拒绝精确网格中可行的狭窄空间动作；覆盖证明不等于连续碰撞证明或任意任务可行。

## 二、空 TCP 与纯运动学接口

`left_tool0`、`right_tool0` 是显式声明的空固定末端坐标系，不作为实体碰撞体。只有同时满足“映射的 TCP、固定关节、叶节点、没有外观/碰撞/惯量”的连杆才可跳过实体几何检查；缺失几何的机器人实体和伪造的运动连杆声明仍被拒绝。

新增纯运动学试运行、±0.1° 点动及正弦接口，使用 URDF 明确给定的预览速度上限。未知质量、电机型号、方向、零位和力矩保持空值；不生成电机空间目标、不计算静态重力或动力学。普通机械臂试运行要求底盘保持固定，导航与停车走原有独立流程。

原完整参数注册及严格运行时加载器未放宽。原软件停止、状态代次、取消及失效结果保护继续包住新接口。普通点动/正弦仍是几何预览，不冒充碰撞路径认证或硬件停止验收。

## 五、剩余验收与交付边界

接续重点是完整客户 CAD 的实际浏览器显示/资源负载、完整双臂任务演示及最终单一 Ubuntu 安装包的独立解压安装验收。当前实际模型路径测试为短关节路径，不将其扩大为所有双臂搬运任务已验收。

原厂家关节、CAD 推定腰轴/几何零位和软件限位保持原值，不代表真机标定。传感器子型号尚未确认；三种模型文件不证明设备已装六维力传感器。动力学、力控、真实 ROS/DDS 和真机执行本轮均未验收。原相邻两主体关节及刚体内部的结构性碰撞排除规则未改变。

用户最终仍应只下载一个 Ubuntu 安装包；本轮模型与验证接续 ZIP 是内部开发资料，不是另一个要求客户额外安装的算法包。

# RM75 简化碰撞运行时接入

2026-10-10，源代码与本地真实 HTTP 接口验收。不是 Ubuntu 安装包或真机验收。

## 改动

- 规划器一次构建碰撞形状、配对和障碍物数组；每个姿态批量计算世界包围盒，先筛除必不相交的配对，剩余配对继续使用原有 15 轴 OBB 判定。
- 不修改关节、路径采样间隔、超时、碰撞排除矩阵或导航地图检查。每次检查仍响应取消，地图检查接收全部形状。
- 模型预处理增加 `--collision-mode lite`：底座 8、躯干 4、双臂 16，共 28 个包围盒。默认 `detailed` 的 64 盒转换保留。每个原始碰撞 OBB 的所有角点均被对应新盒覆盖；原外观、关节和未知动力学参数保持不变。
- 两个无实体的固定 TCP 显式声明，使资源可通过当前模型注册、规划与单包打包接口加载。

## 验证

- 79 项既有机器人回归、49 项工作台回归通过，共 128 项。
- 三种实际 RM75 模型分别对照 258 个姿态，共 774 个；批量算法与逐对原算法的碰撞结果、首个碰撞对完全一致。
- 三种型号均通过 21 样本关节路径，路径结果相同；手腕内障碍物均被拒绝。
- 实际 HTTP：三型号目录、模型加载、保存/恢复、写入活动配置、异步规划成功与停止接口通过。

| 实际模型 | 单次碰撞，逐对→批量 | 完整21样本规划，逐对→批量 |
|---|---:|---:|
| B | 1.583 → 0.054 ms | 53.735 → 19.283 ms |
| 6FB | 1.599 → 0.055 ms | 53.513 → 19.515 ms |
| 6F | 1.597 → 0.056 ms | 53.503 → 19.787 ms |

碰撞微基准重复同一预览姿态，FK 缓存已热；每组100次、重复5组取中位数。完整规划每组独立创建规划器、输出帧，重复7次取中位数；实测约 2.70–2.79 倍。不能外推为所有路径的提速，也不是与无法直接加载的357网格模型比较。环境与原始数值见同名 JSON。

28盒表示比64盒更保守：同样774个姿态，14个被28盒额外拒绝，未观察到64盒阻挡而28盒放行的姿态。盒重叠仍表示可能碰撞，并非精确网格接触；狭窄空间需要时使用 `detailed` 资源，不自动关闭碰撞检查。本次未增加三角网格精确窄相位、连续碰撞、动力学或实物校准。

## 接入与复现

从原始候选包的 `rm75-workbench-bundle` 生成一个独立运行资源目录，原包不覆盖：

```bash
python scripts/prepare_rm75_collision.py /path/to/rm75-workbench-bundle /path/to/rm75-runtime --collision-mode lite
python scripts/check_rm75_collision_runtime.py /path/to/rm75-runtime --output build/rm75-collision-runtime.json
python scripts/robot_workbench.py --model-bundle /path/to/rm75-runtime
```

在整机型号目录选择 B/6FB/6F，加载后按需“写入程序”，使用现有规划按钮。开发资源与旧版公开安装程序不能混同；新版单一 Ubuntu 安装包仍须通过现有 `package_binary.py --model-bundle` 编译和安装验收。此增量不发布安装包，也不驱动设备。

# 统一机械臂工作台 0.2.0

本版将三维工作台、客户硬件参数及双臂/腰部规划统一为 Ubuntu x86_64 软件。
发布范围是固定底盘的运动学、关节路径规划、双手协同任务空间规划和离散碰撞检查。
动力学与 Windows 构建安排在后续版本；不包含真机执行。

## 使用

1. 完整解压 Ubuntu 安装归档，运行 `./OmindOS-Workbench`。
2. 导入或编辑客户完整 URDF 与关节参数。保存版本后可重启自动读取。
3. 展开“客户规划配置”，指定共享腰关节、左右各七轴的顺序以及两个 TCP 连杆。
   关节轴向、安装尺寸、关节限位、工具坐标均从当前 URDF 计算，不使用隐藏的厂家默认值。
   运动学规划不要求质量、惯量或电机力矩参数；含碰撞/外形几何与关节限位的 URDF 即可计算。
   导入、导出独立规划配置可保存自定义映射与障碍物；浏览器也保存最近的规划配置。
4. 关节规划：记为起点，调整主体关节，再点击“规划到当前目标姿态”。
   基座、夹爪和非主体关节在这一步保持固定。
5. 双臂协同：从当前姿态指定共同 XYZ 位移，十五关节联合保持两手相对关系。
   若不可达、碰撞、缺失几何或超出预算，则失败并保留当前姿态，不播放部分路径。
6. 规划支持取消。急停或写入新参数会使旧结果作废；复位不会自动继续规划或播放。

## 算法与模型一致性

`scripts/dual_task_planner.py` 原样复用 Manipulation runtime.2 的 `community/dual_task.py`。
来源提交：`cbe8caf13921002e463355c6a2982e900640c7e0`，来源仓：
`Omind-Robotics/OmindOS-Manipulation`。包清单记录该源文件 SHA256。
通过该内核提供的 FK 与碰撞回调接入工作台模型。
本版不把原来的 Robotiq 参考夹爪替换进客户机器人，也不依赖旧 runtime.2 进程、ROS 或 Docker。

关节路径使用有界 RRT-Connect；所有边以最大 0.01 rad 的单关节增量重新采样检查。
协同内核同时验收两手绝对 TCP 误差及相对位姿误差，并检查每个关节插值样本。
计算预算 60 秒，最多 1000 个成功路径样本；未找到路径不表示不存在可行路径。

## 碰撞检查的准确范围

按每段 URDF 的 collision 几何计算包围盒；未声明 collision 的连杆使用 visual 的包围盒。
盒体保留局部坐标和旋转；球、圆柱与已打包 STL 采用其几何外包围盒。
未支持的网格、缺失几何、未支持形状直接拒绝，不默默忽略。
这是保守几何近似，可能拒绝实际上无碰撞的路径，不能表述为精确网格碰撞。

同一固定装配内部及祖先链相邻两个主体关节之间被结构性排除，避免连接部位的正常重叠；
左右臂不同分支仍检查。实际排除连杆列表随每次结果返回，客户需按自己的装配验收。
环境支持最多 32 个世界坐标系轴对齐盒体，整机最多 256 个碰撞几何包围盒。

只验证离散样本，不保证样本之间连续无碰撞；夹持物仅是约束框架，未建模载荷实体碰撞。
碰撞检查只适用于“规划”入口。原有点动、正弦、连续演示、底盘试跑及 ROS 预览保持运动学功能。
六秒播放时长只方便观察，不进行控制时序、加速度或动力学计算。

## 发布验收

需通过单元回归、源码入口、Ubuntu 原生编译程序、独立解压包及实际浏览器交互验收。
`smoke_planning.py` 对实际运行入口检查协同 TCP、固定基座、障碍物拒绝、关节路径、
参数变更、取消和急停。正式版仅指本页约定的软件功能范围，不表示完成真机或动力学验收。

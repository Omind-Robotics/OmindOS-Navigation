# DM-MC02 USB CDC 主循环适配层

2026-10-08：在原便携通信核心上新增 `om_cdc.c/h`。这是板级移植的
队列与异步发送层，尚未链接 STM32 HAL、启动文件或链接脚本，不能直接烧录。
没有新增电机使能或 CAN 发送接口；原 ARM64 下载包不包含此次开发增量。

## 接线到固件的方法

1. 停止 USB 外设与回调后初始化实例。配置、nonce 和 digest 延续原协议约束；
   nonce 必须来自板卡 RNG，校准参数必须来自实际机器人。
2. 实现 `enter/leave`：保存并恢复中断屏蔽状态，覆盖所有调用此实例的回调。
   不能简单无条件开中断，也不能使用中断里会死锁的普通 mutex。
3. CDC 接收回调把本次 bytes 复制到 `om_cdc_receive`，然后由 HAL 重新准备接收。
   接收、完成、断线回调只排队或设置标志；它们不会解析或发送。
4. 一个主循环持续调用 `om_cdc_poll(instance, HAL_GetTick())`，包括没有 USB
   数据和 USB_BUSY 时。独立调度仍须保证它运行；此层不代替硬件看门狗。
5. `submit` 包装 CDC 异步发送：返回 0 表示接受、1 表示忙、负数表示错误。
   必须在 USB 真正释放发送缓冲后调用 `om_cdc_tx_complete`；STM32 CDC 实际
   完成回调位置、缓存一致性与中断优先级需要在固定厂商工程内核对。
6. 断线、端点错误、CAN 总线错误调用 `om_cdc_link_fault`。错误锁存后只允许
   受控复位；复位前必须停止端点/中断，确认 DMA 不再持有旧缓冲。

接收队列为 256 字节，整块放不下时拒绝并锁存故障。发送缓冲在异步发送
完成前保持不变。BUSY 重试和已接受但未完成的发送，共用从首次生成回应
起算的 20 ms 测试超时；计时支持 uint32 回绕。20 ms 是软件台架约束，
不是实机控制频率。只有主循环消费数据，所有队列与回调标志由临界区保护。

## 验证与下一步

`python3 -m unittest discover -s tests -p 'test_dm_mc02*.py' -v`
运行原协议测试与新增 CDC 测试。新增测试实际编译 C 层，覆盖分包、连续请求、
异步缓冲持有、队列溢出、BUSY 超时、完成丢失、断线锁存、忙期间的协议
看门狗、tick 回绕和发送错误，共八个场景；没有硬件报文。

下一步是在固定厂商 STM32H723 工程中连接上述回调、RNG 和定时调度，
然后完成三路经典 CAN 扩展帧接收与反馈。Jetson 安装、USB 实际时延、
板卡烧录、RS04 参数回读和实机停止行为仍待验证。

# 统一客户发行版：四足优先，保留轮式支持

2026-10-08 确定的产品范围：一个 OmindOS Navigation 客户发行版本，共用导航核心、安装入口、任务接口和版本管理；以配置及适配器区分四足、差速轮式、全向轮式。先完成四足客户交付，轮式继续作为同版本回归对象。

本文及配置检查程序是客户版开发增量，不是已完成正式硬件发行的声明。现有公开版本仍为 `0.2.0-preview.1`。

## 当前基础与实际缺口

| 项目 | 已有内容 | 正式客户交付仍需完成 |
| --- | --- | --- |
| 通用核心 | 三种平台共用 ROS 2 Humble 平面导航示例、限速和超时检查 | 目标硬件上的定位、规划、避障与任务验收 |
| 客户安装 | Linux amd64 离线 Docker 包、校验、独立安装和三平台仿真 | 确认客户计算平台；ARM64 需另构建并验证同版本架构包 |
| 四足接入 | 通用机身速度配置；仓库保留旧 Go2 平台材料 | 确认新底盘控制器与 SDK，完成实际适配、状态回读和停机测试 |
| 轮式接入 | 差速/全向配置，差速不允许横移 | 对应电机/底盘驱动及停机、里程计实测 |
| 验证 | 公开预览记录含 20 项检查和三平台到达/连续零指令 | 物理机器人、传感器、环境和连续运行证据 |

现有预览包不包含 FAST-LIO/Livox/Unitree SDK、C++ 三维规划链或硬件 bringup；不得将预览二维示例描述成这些模块已经完成客户交付。

## 分层责任

- 导航核心：目标、地图与定位、路径和导航速度请求。
- 平台适配器：配置校验、坐标/单位转换、底盘允许的速度自由度、状态与故障回读、使能/停机语义。
- 底盘控制器：四足步态、平衡和关节控制，或轮式电机/制动控制；自身还必须处理上位机退出、失联或进程崩溃。仅由上位机发送零速度，不能保证失联后的实体停止。

一个版本不等于所有底盘免适配。四足、差速和全向可以共用版本；CPU 架构不同则提供同版本的不同安装包。

## 现在可用的接入检查

三份 `config/customer/*.example.json` 使用同一结构。未取得的硬件事实保留 `null`，不把 Go2 接口、x86 主机或已有步态算法当作新底盘的已知事实。

```bash
python3 scripts/check_customer_profile.py config/customer/quadruped.example.json
python3 scripts/check_customer_profile.py config/customer/quadruped.example.json --require-hardware
python3 -m unittest discover -s tests -p 'test_customer_profile.py' -v
```

第一条检查模板结构；第二条会在硬件信息不足时返回 `HARDWARE_DETAILS_REQUIRED` 并退出 2。程序不访问网络、不加载 SDK、不发 ROS/底盘指令。填齐声明仅表示配置完整，报告始终保留 `hardware_validated: false` 和 `motion_authorized: false`，真实验收需独立记录证据。

字段需由实际控制器资料和计算平台确认：型号、CPU 架构、控制协议、SDK 版本、适配器、里程计来源、停止指令含义、底盘失联超时、物理急停和底层运动控制是否就绪。四足的 `locomotion_controller_ready` 指已有步态与平衡控制；轮式指已有电机及底盘速度控制。

## 交付顺序与完成条件

1. 确认四足硬件和底层控制接口，落地适配器；统一配置结构保持不变。
2. 独立构建客户包，补齐用户指南、API、配置示例、版本/校验、诊断日志与卸载/升级流程。
3. 无实体连接完成三平台回归及真实 ROS 消息层的异常输入、超时、急停锁存、重启失能和驱动失联测试。
4. 硬件到位后依次核验只读状态、零指令、受控低速、到达/避障、任务取消和失联停机。分别记录底盘、SDK、传感器、参数、日志与人员确认。
5. 基于实测结果冻结客户发行范围；未测项目明确标注，不将仿真通过记为实机验收。

当前需要首先确认：即将完成的四足使用哪种底层控制器，步态/平衡控制是否已有，以及该控制器向导航提供什么速度与状态接口。

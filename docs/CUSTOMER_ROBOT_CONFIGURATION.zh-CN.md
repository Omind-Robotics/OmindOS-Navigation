# 客户机器人配置：URDF → 电机 → 其他参数

客户版以 MEVIUS2 原版模型和控制参数作为四足默认参考。与原设计相同的参数可沿用；不同的部分按下列顺序填写。每台机器人保留自己的配置副本和版本，原版参考文件作为后续对照。

配置填写模板：[mevius2.customer-record.json](../config/robot_profiles/mevius2.customer-record.json)。模板用于记录模型与参数；客户通过 [参数 API](ROBOT_PARAMETER_API.zh-CN.md) 提交 URDF 与关节驱动参数，保存和读取配置版本。记录模板并非 API 请求格式，API 页面提供字段与调用方法。当前尚未接入 ROS 2 运动控制加载器。原版仿真复现见 [MEVIUS2 适配记录](MEVIUS2_INTEGRATION.zh-CN.md)。

## 参数分类和保存位置

填写顺序仍为 URDF、电机、其他参数；参数本身按下表区分，避免把控制增益当作机械属性。

| 类别 | 内容 | 保存位置 |
| --- | --- | --- |
| 运动学 | 连杆尺寸、关节连接/轴向/位置、运动范围 | URDF 的 link/joint、origin、axis、limit |
| 刚体动力学 | 每个连杆的质量、质心、惯性张量 | URDF 的 link/inertial |
| 关节被动动力学 | 关节阻尼、摩擦 | URDF 的 joint/dynamics；核对仿真器导入结果 |
| 电机与传动 | 型号、减速比、方向、零点、反馈坐标、输出能力 | 每关节驱动/传动配置；需要时生成对应 transmission 描述 |
| 控制与运动任务 | Kp/Kd、控制频率、站立目标、速度指令限制、步态策略 | 控制器及任务配置 |

**动力学既与连杆有关，也与关节和传动有关。** URDF 能记录质量、质心、惯量及基本关节动力学；电机力矩常数、转子惯量、传动效率、通信映射等还需匹配实际驱动和仿真接口，不能假定所有工具会自动读取并生效。

电机轴角度与关节输出角度要明确区分；若设备反馈已经换算到关节侧，不应再次乘除减速比。减速比、方向、零点以及力矩/速度换算须使用同一约定。关节最大力矩和速度还应与 URDF limit 对齐。PD 的 Kd 是控制器增益，不等同于 joint/dynamics 的物理阻尼。

参考：[ROS 官方 URDF 物理属性说明](https://github.com/ros2/ros2_documentation/blob/rolling/source/Capabilities/Simulation/URDF/Adding-Physical-and-Collision-Properties-to-a-URDF-Model.rst)、[ros2_control Humble SimpleTransmission](https://control.ros.org/humble/doc/api/classtransmission__interface_1_1SimpleTransmission.html)。

## 1. URDF 模型

填写机器人 URDF 路径和相关网格文件。默认参考为 MEVIUS2 的 `models/mevius2_dae.urdf`；碰撞/仿真参考另有 `models/mevius2_stl.urdf` 和 `models/scene.xml`。

自定义模型应给出连杆尺寸、质量、惯量、关节名称/轴向/限位、碰撞形状和传感器安装坐标。长度用 m、质量用 kg、惯量用 kg·m²、角度用 rad。网格与模型一起交付，使用可解析的相对路径或 ROS 包路径。

修改 URDF 后要同步对应的 MuJoCo/训练模型；本版本还未实现从任意客户 URDF 自动生成可用运动策略。

## 2. 电机型号与通信

默认参考为 12 个 RobStride03、两路 SocketCAN。按关节填写型号、协议/驱动、CAN 接口、ID、正方向和传动比。传动比应说明是“电机角 / 关节角”还是其他定义，并与驱动反馈单位一致，避免驱动已换算后重复换算。

| 腿 | 关节顺序 | CAN | ID | 原版方向 |
| --- | --- | --- | --- | --- |
| 左后 BL | collar / hip / knee | can0 | 10 / 11 / 12 | +1 / −1 / −1 |
| 右后 BR | collar / hip / knee | can0 | 7 / 8 / 9 | +1 / +1 / +1 |
| 左前 FL | collar / hip / knee | can1 | 4 / 5 / 6 | −1 / −1 / −1 |
| 右前 FR | collar / hip / knee | can1 | 1 / 2 / 3 | −1 / +1 / +1 |

表格是原设计的映射。原仓库的电机零点属于原机个体标定；模板中的零点待填写本机标定值。更换电机型号时还要核对扭矩/速度范围、控制模式及通信驱动是否支持。

## 3. 关节、控制与传感器参数

| 参数 | 原版参考值或填写位置 | 什么时候需要修改 |
| --- | --- | --- |
| 站立关节角 | 每腿 `[0.0, 0.7, -1.2]` rad，按上述顺序 | 腿长、轴向或关节结构变化 |
| PD 增益 | 每关节 Kp = 50、Kd = 2，沿用上游定义 | 电机、负载、控制模式变化；同时核对驱动单位 |
| 控制频率 | 策略 50 Hz，仿真/电机环 200 Hz | 实际计算与驱动能力变化 |
| 策略动作缩放 | 0.2 | 配合策略训练和控制定义调整 |
| 质量、惯量、载荷 | 写入模型及配置记录 | 电池、外壳、雷达、载荷变化 |
| IMU | 型号、话题、轴向、安装位姿 | 更换设备或安装位置变化 |
| 雷达和里程计 | 型号、数量、外参、坐标系、数据来源 | 传感器组合或位置变化 |
| 计算平台 | CPU 架构、系统、驱动/固件版本 | 更换主机或升级系统 |

默认参数是可复现的起点，不是所有电机和结构的通用最优值。模型参数发生变化时，应保持模型、实际机器人和所用策略对应。

## 4. 客户后续修改参数

1. 复制本机上一版记录，例如 `robot-a.config-v1.json` → `robot-a.config-v2.json`，保留旧版可回退。
2. 按“URDF → 电机 → 其他参数”修改对应项，在 `changes` 中记录修改前后值、原因和日期，并更新 `profile_revision`。
3. 关联同一版模型、控制参数、驱动与策略，先检查单位、关节映射，再运行对应模型的仿真。
4. 模型/重量变化后评估原策略；结构、传动或电机变化较大时可能需要驱动适配和重新训练。仅换 URDF 或填写电机名称不会自动完成这些工作。
5. 将验证通过的配置设为该机器的使用版本，并保存模型、配置和验证记录。实体零点和安装外参按本机确认。

升级 OmindOS 时保留客户配置副本；默认参考参数另存版本。若升级改变了参数格式，应提供迁移说明和变更对照。

## 5. 填完后检查

确认模型文件可加载，关节名称唯一且映射齐全，单位一致；再检查电机型号/通信驱动、零点、传感器坐标、频率与负载。客户模型的仿真应包含站立、行走、转向及停止，验证结果绑定模型和配置版本。

当前通用接入检查命令仍用于 `config/customer/quadruped.example.json`：

```bash
python3 scripts/check_customer_profile.py config/customer/quadruped.example.json
```

本页的机器人参数记录与该接入检查文件是不同用途；参数 API 已支持注册/读取，控制器自动加载和自动训练尚未实现。后续控制加载器接通后，客户使用已验证的本机配置启动对应平台。
